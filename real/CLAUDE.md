## 한 줄

도서관 청구기호(852 ▼h)를 매기는 사서-AI 협업 에이전트.
**현재 파일럿은 모든 비승계 책을 사서가 확정하고, 충분히 검증된 뒤 쉬운 책만 자동화한다.**

## 지금 구조 — 독립 shelf_fit + 3단계

설계 정본은 `docs/design.md`, 흐름도는 `docs/system_flow_draft.md`, 시간순 경위는
`docs/devlog.md`에 있다.

- 점수 `shelf_fit`은 **책 한 권 × 서가 한 곳**만 놓고 매긴다. 다른 후보·출처·단계·문턱은
  그 호출에 넣지 않는다. 그래야 같은 눈금이 되고 문턱을 재산정할 수 있다.
- 후보는 082 → +종합서지 → +키워드로 **누적**되고, 각 단계는 **새로 생긴 후보에만** 점수를 매긴다.
  같은 서가는 전 과정에서 **딱 한 번** 평가된다.
- 정렬·수렴 판정은 전부 코드가 정한다(`src/decide.py`). 판정은 `converged` 불린
  하나다 — True면 ✅ 1순위가 정해졌습니다, False면 ⚠️ 사서가 가른다. **확정은 어느
  쪽이든 사서가 앱에서 버튼으로 한다**(수렴이면 클릭 한 번일 뿐). 기록은 runs/ jsonl.
- 2026-08-25 다섯 프롬프트 비교에서 `two_axis`가 수렴 사례 22/24로 가장 좋아
  `prompts/systemprompt_shelf_fit.txt`에 운영안으로 반영했다. 두 축은 주제·관점과
  자료 성격·용도이며 최종 점수는 50:50 산술평균이다.
- **판정은 점수+격차 두 조건이다(2026-09-02).** `THRESHOLD_2=0.80`(1위 점수 바닥) +
  `GAP_MIN=0.15`(1·2위 격차). 둘뿐이다 — 동점(격차 0.00)은 GAP_MIN이 이미 잡으므로
  별도 조건을 두지 않고, 대신 **점수가 같으면 공동 순위로 표시**한다(`decide.with_ranks`,
  1·1·3식 — 화면 차례는 번호 문자열 정렬이라 그걸 1위·2위로 세면 없는 우열이 생긴다).
  근거는 two_axis 8-25 원물
  12건×3회 관측(devlog 9-02(3)) — 사람이 갈린 책은 점수가 높아도 gap이 좁다(#9).
  in-sample 잠정값이라 기준선 회차에서 재확인한다.
- **문턱은 두 곳에서 작동한다. 둘 다 같은 두 조건을 쓴다 — 별도 문턱은 없다.**
  스위치는 `decide.STAGE2_GATE` 하나뿐이다(기본 **on**): 082+종합서지까지로 이미
  수렴이면 **키워드 단계를 건너뛰고 종결**. 8-25 실측 #3·#4·#6이 정답으로 3/3회 종결,
  갈린 4건은 전원 통과 못 함. 실험으로 전 케이스를 3단계까지 보고 싶으면 off.
  평가 회차(evaluate·비교 스크립트)는 분포에 구멍이 나지 않게 **끈다**.
- **구 `escalate`·`AUTO_CONFIRM`은 제거(2026-09-02).** 앱에 "사람 안 거치는 경로"가
  없어서(확정 = 사서의 버튼 클릭 → runs/ jsonl 한 줄, 규약 4) escalate은 항상 True인
  죽은 필드였고 AUTO_CONFIRM은 문구만 바꾸는 스위치였다. 되살리지 말 것 — 배치 모드를
  실제로 만들 때 그 코드가 자기 스위치를 갖는다.
- **1단계 게이트(THRESHOLD_1·EARLY_STOP)는 제거** — 오답 082가 정답 082보다 점수가
  높은 역전이 실측돼 값이 존재하지 않는다. 082는 최초 후보일 뿐이다.
- 구 구조(`lib_copilot_a`/`_b` 두 벌, classify.py 한 덩어리)는 2026-08-19에 없앴다 —
  경위는 devlog.

## 구조

`real/`을 프로젝트 루트로 보고 여기서 실행한다.

```
  run.py       책 한 권 돌려보기   python run.py <book.json>       ← 터미널 출력만
  app.py       데모 화면          streamlit run app.py

  src/         라이브러리 (직접 실행하지 않는다)
    pipeline.py   3단계 배선 — **이야기 전체는 이 파일 하나로 읽는다**
    schema.py     데이터 계약 (BookInput · CandidateNumber · ShelfFitAssessment · CandidateDecision)
    retrieve.py   후보 찾기 (082 · 종합서지 · 키워드검색)   + union_db.py · sogang_db.py
    fit.py        LLM-F  독립 shelf_fit — 책 1권 × 서가 1곳, 후보마다 1회 · 인용도서 코드 검증
    keywords.py   LLM-K  검색어 3~5개 — 책 정보만 본다
    decide.py     정렬·수렴 판정(두 조건)·2단계 게이트 — LLM 0회
    llm.py        API 호출·재시도·원물(trace) 기록 — "무엇을 묻는가"를 모른다
    prompt.py     지문 읽기 + 책/서가 블록 조립
    aladin.py     입력 보강 · tokens.py 토큰 규칙

  prompts/     시스템 프롬프트 — **코드가 아니라 파일이다**
                 systemprompt_shelf_fit.txt  독립 fit (후보마다 같은 지문)
                 systemprompt_keyword.txt    검색어 만들기
  data/        책소개 캐시 · 본교/종합 DB(커밋 안 함)
  runs/        데모에서 사서가 확정한 기록

  ../experiment/  골든셋 · 평가 CLI · 다섯 비교 프롬프트 · 실험 결과

```

흐름: **보강 → 0차 승계 → 【1단계】082 → 【2단계】+종합서지 → 【3단계】+키워드 → 코드 판정**
각 단계는 새 후보에만 fit 호출을 하고, 판정은 코드가 한다.

## ⚠️ 반드시 지킬 것

1. **외부에서 받아온 산출물은 커밋하지 않는다** — 드라이브로 배포한다.
   `data/sogang_db_final.db`(1.3GB) · `data/union_db.json` · `data/aladin_cache.json`.
   `git add data/`를 통째로 하지 말 것. 골든셋은 `../experiment/data/scenarios/`에 있다.
   책소개 캐시는 출판사 저작물이라 저장소가 Public이 되면서 뺐다(2026-08-18).
2. **평가 경로를 바꿨으면 `--label`을 바꿔 새 회차로 남긴다.** 회차 산출물은 덮어쓰지 않는다.
3. **LLM 호출은 `llm.ask()`를 통해서만, 부르는 곳은 `fit.py`·`keywords.py` 둘뿐이다.**
   지문도 둘뿐이다(fit은 후보마다 같은 지문을 다시 쓴다). 다른 파일에서 부르지 않는다.
4. **결정 결과를 장서 DB에 되쓰지 않는다.** 누출을 매번 새로 만드는 짓이다. 앱은 읽기 전용.
5. **홀드아웃을 모든 조회에 통과시킨다** — 승계·서가·**키워드 검색** 전부.
   안 걸면 그 책 자신이 검색에 걸려 자기 번호를 근거로 자기 번호를 찾는다
   (`794.801`은 6권인데 그중 1권이 「게임으로 철학하기」다).
6. **스키마에 뺐던 필드를 다시 넣지 말 것** — `confidence`/`ambiguity`/`signals`.
   원칙: **시스템이 이미 아는 것은 LLM에게 묻지 않는다.**
7. **키워드 추출 호출에 서가를 보여주지 말 것.** 082 서가를 보여주면 그 어휘로 물들어,
   082가 오답인 케이스에서 검색이 오답 쪽으로 끌려간다 — design.md §3.3.
8. **fit 호출에 다른 후보를 보여주지 말 것** (spec §2 「넣지 말 것」). 다른 번호·출처
   (082/종합서지/키워드)·득표수·현재 단계·문턱·과거 판례 전부. 하나라도 들어가면 점수가
   독립 적합도가 아니라 후보 비교 점수가 되어, 문턱 재산정이라는 이 구조의 목적이 무너진다.
   또한 **같은 서가에 두 번 점수를 매기지 말 것** — 앞 단계 점수를 그대로 쓴다.
   **082도 넣지 말 것** — LLM에 주는 책 정보는 `prompt.book_content_block()` 하나로 통일돼
   있고 거기에 082가 없다. 새 호출부를 만들 때 다른 블록을 손으로 조립하지 말 것.

## 실험과 결과를 읽을 때

**LLM 판단이라 같은 조건에서도 실행마다 흔들린다.** `--runs=3`이 기본이다.
**항상 맞음 / 항상 틀림 / 흔들림**으로 나눠 봐야 한다. 고칠 가치가 있는 건 "항상 틀림"이고,
"흔들림"을 쫓으면 노이즈를 쫓는 것이다.

평가 코드와 산출물은 `../experiment/`에만 둔다. 실제 구현 로직은 복사하지 않고
`real/src/`를 import해 같은 파이프라인을 평가한다.
